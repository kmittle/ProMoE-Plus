实验 / Experiment: B_clean_route_teacher_ratio0
model_name: ProMoE_TC_B_clean_route  |  config: configs/004_ProMoE_B_clean_route_teacher_ratio0.yaml
基线 / Baseline: 基础 ProMoE-TC（cond/uncond 分流、静态 cluster_centers 余弦原型路由、top-1 token-choice、shared expert、routing contrastive loss）；直接父变体 / Parent: 基础 ProMoE-TC（clean_route 是新家族，只有 MoE block 继承会议版 SparseMoeBlock；本批四个实验互为 sibling，只差 contrastive_source 和 teacher_sigma_ratio）

核心改动 / Core changes（相对基线，重点优先）:
1. clean-route 路由蒸馏：每个训练 step 对同一 batch 先跑一次 torch.no_grad 的 teacher 前向（同一 latents、同一噪声，teacher_sigma_ratio=0.0：teacher 输入就是干净 latent z、timestep t=0（σ_a=0），对齐的是"全局"目标：任何噪声水平的路由都向干净路由看齐），再跑正常的 student 前向。每个 MoE block 里，student 的 cond-token 路由分布 p = softmax(cos(h_S, cluster_centers)/τ) 通过 align_lam·KL(q‖p) 对齐 teacher 的软标签 q = softmax(cos(h_T, cluster_centers)/τ)，其中 align_lam=5e-4、align_temperature τ=0.07。q 是固定目标；cluster_centers 两侧共用且不 detach；类别 dropout 只抽一次、两次前向共用；teacher 只跑 prototype-routed 的图像；teacher 的 autocast 权重缓存在 student 前向前清空（否则 bf16 下 student 权重拿不到梯度）。推理和采样不跑 teacher，与基础 ProMoE-TC 相同。
2. contrastive_source=teacher（A 臂）：不再在 student token 上算会议版 routing contrastive loss，改为用 no-grad teacher 的 token（已 detach）和 teacher 的 top-1 分配计算同一个 InfoNCE（×routing_contrastive_lam=1），因此只更新 cluster_centers，不改主干；prototype 由干净（或更干净）特征的簇来定义。student 的路由只受对齐（经 student cosine）和 FM（经 identity gate）约束。相对 sibling B_clean_route_student_ratio0 只差对比学习放在哪一侧。
3. teacher 噪声 / teacher_sigma_ratio=0.0（干净 teacher）：相对 sibling B_clean_route_teacher_ratio0p5（teacher 在 σ_a=0.5σ、同一份噪声、t_a=0.5t 的"局部"目标）只差这一项。σ=0 在训练里几乎采不到（logit-normal 下 σ<0.05 约 0.16%），smoke 中检查过此时 teacher 路由未塌缩（图内最常用专家覆盖约 47%、全局 max share 约 0.37）。
4. 参数与训练设置：不新增参数，参数和初始化与 ProMoE_TC_B 完全一致（step-0 同一模型，checkpoint 可互换），align_lam=0 加 contrastive_source=student 时训练 step 与 ProMoE_TC_B 逐位一致（test/test_models_ProMoE_TC_clean_route.py，含 bf16 autocast 与两卡 DDP）。从零训练：global_seed=0、global batch 256、4 卡、lr 1e-4 常数、无 scheduler，训练到 300K 后 CFG 1.0/1.5 各采样 50K 评测，不自动续训到 500K；两个 FID 都严格优于 30.86 / 9.73 才在自己的输出目录续训到 500K。teacher 前向使每步训练时间增加约 36%–44%（smoke 实测）。
