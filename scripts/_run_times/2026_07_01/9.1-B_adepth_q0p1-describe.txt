实验 / Experiment: 9.1-B_adepth_q0p1
model_name: ProMoE_TC_B_adepth  |  config: configs/004_ProMoE_B_adepth_q0p1.yaml
一句话 / TL;DR: 让模型自己判断哪些图像块“简单”哪些“难”，把简单块的算力省下来匀给难块——简单块直接跳过专家、难块多算一遍，总算力不变，看能不能提升质量。这是省/加比例最小的一档。

这个实验在做什么（大白话）:
1. 核心想法（改进组三，仿 MoD 做法，alloc_mode=fixed_q）：每个 MoE 层新增一个小打分器(depth_gate)给每个有类别的图像块打一个“难度分”，然后按固定比例把这些块分成三档——最简单的一批直接跳过专家不算(省算力)、中间的照常算一遍(和原来一样)、最难的一批多算一遍(第二次再走同一个专属专家，相当于给它加深处理)。因为“跳过的数量”正好等于“加深的数量”，所以总的计算量和原来完全一样，只是把简单块省下的算力挪给了难块。注意只加深不加宽，公共专家和无类别的块都不受影响。
2. 本实验的比例（depth_q=0.1）：最难/最简单各挑 10%，也就是 10% 跳过 + 10% 加深 + 剩下 80% 照常。这个比例不是一上来就用满，而是从 0 慢慢涨上去(前 5000 步热身，depth_warmup=5000)。
3. 它在这组里的位置：这是省/加比例从小到大 0.1 / 0.2 / 0.3 / 0.4 四档扫描里最保守的一档，四个实验只有这个比例不同，用来看“挪多少算力最划算”。
4. 打分器和加深开关都是零初始化、比例从 0 起步，所以在相同参数状态下第 0 步的前向机制与原始 ProMoE 一样；新增打分器仍会改变随机参数的生成顺序，因此不能声称 fresh 权重逐项相同。本次补测从空目录、`global_seed=0` 重新训练，不加载原模型存档，避免把 warm-start 当成改进来源。（要求 top_k=1，即每块只走一个专属专家。）
