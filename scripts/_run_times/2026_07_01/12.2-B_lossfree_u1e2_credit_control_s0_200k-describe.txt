实验 / Experiment: 12.2-B_lossfree_u1e2_credit_control_s0_200k
model_name: ProMoE_TC_B_lossfree  |  config: configs/004_ProMoE_B_lossfree_u1e2_credit_control_s0_200k.yaml
基线 / Baseline: 基础 ProMoE-TC（conditional/unconditional 分流、cosine prototype top-1 路由、shared expert 和 routing contrastive guidance）；直接父变体 / Parent: Loss-Free u=1e-2。文件名中的 `200k` 是旧队列把同一条 seed-0 训练轨迹交给另一个窗口时留下的调度名称，不是科学上的停止条件，也不是独立的 200K 实验。

核心改动 / Core changes（相对基线，重点优先）:
1. Loss-Free count balancing：`use_lossfree_bias: True`、`bias_update_rate: 0.01`。每个 routed expert 有一个非训练 `expert_bias` buffer；top-1 选择使用 `cosine score + expert_bias`，实际 routed weight 仍使用无偏 cosine score。训练时按跨 GPU 汇总的本 batch token count 更新 bias，因此不增加 trainable parameters，bias 初始为零时与基础 ProMoE 的初始选择一致。
2. 诊断目的 / diagnostic role：保持 Base 的 LR `1e-4`、global batch `256`、12 个 top-1 routed experts、shared expert 和 routing-contrastive 设置不变，以 `global_seed: 0` 训练。此历史 wrapper 本身的协议是 `num_steps: 201000`、只评估 200K；后来单独的运行时交接脚本从该 checkpoint 继续到 300K，不能把交接动作改写成这份历史实验的设置，也不能把 200K 当作完整的最终结论。该 checkpoint 只用于检查 Loss-Free 是否压低 count imbalance，以及后续是否仍有 count-adjusted learning-credit mismatch。
3. 可审计运行设置：使用本地 encoded ImageNet latents，`img_num_workers: 16`，每 10K 保存 checkpoint；输出写入仓库 `outputs/ProMoE_TC_B_lossfree/004_ProMoE_B_lossfree_u1e2_credit_control_s0_200k/`。200K 后按既有协议生成 50K samples，并在 guide scale `1.0/1.5` 下评估；slot `12.2` 使用 GPU 4-7。
