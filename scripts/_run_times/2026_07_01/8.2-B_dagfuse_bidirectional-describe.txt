实验 / Experiment: 8.2-B_dagfuse_bidirectional   (slot 8.2, GPU 4-7)
model_name: ProMoE_TC_B_dagfuse  |  config: configs/004_ProMoE_B_dagfuse_bidirectional.yaml
基线 / Baseline: 基础 ProMoE-TC（两步路由：class==1000 走 uncond 专家 + 静态可学习 cluster_centers 余弦相似度原型路由，top-1 token-choice，shared expert，路由 contrastive 损失 via AddAuxiliaryLoss）；直接父变体 / Parent: 即基础 ProMoE_TC_B 本身（本变体只在 shared↔conditional 合并处新增融合，conditional 聚合不变）；兄弟臂 / siblings: 另两个方向 cond_from_shared、shared_from_cond。

核心改动 / Core changes（相对基线，重点优先）:
1. DAG-MoE 风格的 shared↔conditional 结构化融合 / structural fusion（DAG-MoE, arXiv 2606.01062, Eq 7-11）：把 DAG-MoE 的结构化聚合从「被选专家之间」迁移到两角色节点 {C = routed/conditional 局部输出, S = shared 全局输出}。用一个 K=2 的门控边算子 `DAGFuseModule`（FusedRMSNorm → down_proj d→d_g=64 → combined_proj d_g→4·d_g 拆 g_src/g_tgt/v_src/v_tgt → gate=GELU(g_src[i]+g_tgt[j]) · value=v_src[i]+v_tgt[j] → 对 key 求和 → 零初始化 up_proj d_g→d → 残差，`fusion_num_iter`=L=1）。仅对 cond token 生效，uncond token 完全不受影响，shared 始终加回（融合是「补全」而非「替换」）。conditional 专家聚合本身不改。
2. 融合方向 / fusion_arm = `bidirectional`（C↔S，对称对照臂）：C、S 两节点并行更新，各自读更新前的 {C, S}（含自环）= 标准 DAG-MoE 在 2 节点上的一次迭代。作为两个单向臂（cond_from_shared / shared_from_cond）的对称对照，检验双向互参是否优于单向。相对兄弟臂仅 `fusion_arm` 取值不同；三臂共用同一个 DAGFuseModule、参数完全相同，方向是唯一实验变量（iso-param 消融）。
3. step-0 等价 / identity：up_proj 零初始化（在 `DiT.initialize_weights` 的 `_basic_init` 全量 xavier 之后再次置零）⇒ 模块初始输出 0 ⇒ 块输出 = C+S，与 base ProMoE_TC 前向逐比特一致（已数值验证 max|Δ|=0.0），base ckpt 可 `strict=False` 加载。其余（两步路由 / 静态 cluster_centers / top-1 token-choice / 路由 contrastive 损失）与 base ProMoE-TC 相同；训练/采样超参对齐已跑过的 `configs/004_ProMoE_B.yaml`。
