实验 / Experiment: 3.3-B_ecmix_step_cos0p50
model_name: ProMoE_TC_B_ecmix  |  config: configs/004_ProMoE_B_ecmix_step_cos0p50.yaml
基线 / Baseline: 基础 ProMoE-TC（conditional routing + 静态 `cluster_centers` 原型 cos-sim top-1 token-choice、shared expert、routing contrastive InfoNCE）；直接父变体 / Parent: 即基础 ProMoE-TC（会议版 `models_ProMoE_TC.py`；本模型只有 MoE block 继承其 `SparseMoeBlock`，`ratio: 0` 时逐位一致）

核心改动 / Core changes（相对基线，重点优先）:
1. EC step 比例余弦退火（`ecmix_config.mode: step`, `schedule: cosine`, `ratio: 0.5`, `anneal_steps: 500000`）：EC step 比例 p = 0.5 × ½(1 + cos(π·min(step, 500000)/500000))，从 0.5 降到 500K 时的 0（300K 时约 0.17）；哪些 step 走 EC 由 p 的积分按 step 号均匀排开（前期约隔一步一次，500K 之后不再有）。被选中的 step 走完整 EC-BC step：每个专家从本卡 batch 的 cond token 中取 cos-sim 最高的 k = T/12 个，门控为 cos-sim 分数，同一 token 被多个专家选中时输出相加、未被任何专家选中的 token 只经过 shared expert，该步 routing contrastive loss 用 EC 版；其余 step 为官方 TC step（TC 路由 + TC loss）。
2. 推理不变：eval / 采样恒为官方 TC。训练日志记录 `ecmix_ratio`、`ecmix_ec_step`，以及按 TC 分配算的负载 CV / 最大份额 / 活跃专家数（EC step 上也记录 TC 会怎么分）与两种对比损失。
3. 训练设置对齐会议版 `configs/004_ProMoE_B.yaml`（global batch 256、lr 1e-4、501K 步、seed 0），但为 2 卡（每卡 128 张图，TC loss 与 EC 选择都在单卡 batch 内计算）；本批不设 300K 门禁、不做 300K 评测，只在 500K 采样评测（CFG 1.0 / 1.5）；中断后可用 `PROMOE_RESUME=1` 从本实验自己的 checkpoint 续跑。
