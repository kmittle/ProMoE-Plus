实验 / Experiment: 1.4-B_expert_cos_lam3p0
model_name: ProMoE_TC_B_expert_cos  |  config: configs/004_ProMoE_B_expert_cos_lam3p0.yaml  |  GPU 6-7（2 卡）
基线 / Baseline: 基础 ProMoE-TC（conditional routing + 静态 cluster_centers 原型 cos-sim top-1 token-choice、shared expert、routing contrastive InfoNCE）；直接父变体 / Parent: 即基础 ProMoE-TC（会议版 models_ProMoE_TC.py；本模型只有 MoE block 继承其 SparseMoeBlock，且只新增一项训练期损失，expert_cos_lam=0 时与之逐位一致）

核心改动 / Core changes（相对基线，重点优先）:
1. 新增“专家 pooling 表征的余弦正则”：每个 MoE block 内，每个 routed expert 对它实际收到的 token 的输出取均值（不加 router 权重）得到 pooled 表征，K 个向量先中心化，再用 mean((cos_ij - target)^2) 把两两余弦拉向 target = -1/(K-1)。中心化后两两余弦的均值恒等于 -1/(K-1)（sum(c_i)=0 的推论，各池范数相等时严格成立），该值对应 K 个方向排成正单纯形、即最均匀分散的配置，损失下界 0 可达。不用 relu(cos-0) 是因为实测 K=12、768 维时中心化后最大余弦仅 -0.008，relu 会把整项裁成恒 0——正是历史上 expert_contra 的 exp(-L2/tau) 因 tau 失配而恒为 0 的同类陷阱。梯度只到专家参数（及经 token 表征回流到更前层），不直接改路由。
2. 本 arm 的正则权重 expert_cos_lam = 3.0；四个 arm 只差这一个数（全部取值为 0.1 / 0.3 / 1.0 / 3.0）。约 MSE 梯度的 315%，故意设成过强：用来确认剂量曲线是否平滑单峰。注意 grad clip 0.5 在 Adam 之前，此档会占走专家梯度预算的约一半，若变差需区分“机制有害”与“预算被抢”。
3. 训练设置：2 卡（每卡 128 张图，global batch 仍为 256）、seed 0、lr 1e-4、501K 步、会议版超参数；所有 arm 统一使用 10K 步的 lam 线性 warmup（step 0 时该项相对强度是 300K 的 1.9 倍，warmup 避免它主导专家分化的早期，统一施加不构成 arm 间的额外因素）。300K 和 500K 都采样评测（CFG 1.0 / 1.5），300K 不触发停止。
   注意可比性：2 卡运行与 4 卡的 canonical baseline（300K 30.86 / 9.73、500K 24.44 / 6.39）不能直接比——pooled 表征和路由对比的类中心都是每卡各自统计的，卡数会改变它们。判据应是四个 arm 之间随 lam 的剂量趋势，baseline 数值只作粗略背景。
   中断后可用 PROMOE_RESUME=1 从本实验自己的 checkpoint 续跑。
