# 为什么先检查“当前最优”和“几步后最优”是否一致

更新日期：2026-08-29

## 要检查的问题

ProMoE 的分配员在当前去噪步给每位专家打分。但生成图片不是只算一步，当前输出会成为下一步输入，也可能改变后面多个专家层的分配。

因此这里先问：

> 在每位专家工作量完全不变时，一次交换当前看起来更好，继续走 2、4、8 个去噪步以后是否仍然更好？

这个问题若不存在，就没有理由再设计“长程专家信用”训练。先跑 500K 方法再解释动机，会变成事后讲故事。

## 最接近的已有工作

| 工作 | 已经做了什么 | 我们不能怎样宣传 |
| --- | --- | --- |
| [SharpMoE](https://arxiv.org/abs/2606.26938) | 在扩散 MoE 中利用短轨迹，并约束整段轨迹上的分配 | 不能说首次让扩散 MoE 路由考虑轨迹 |
| [MoE-GRPO](https://arxiv.org/abs/2603.24984) | 把多次专家选择当成动作序列，用最终奖励训练分配员 | 不能说首次用长程奖励训练 MoE 路由 |
| [When Are Experts Misrouted?](https://arxiv.org/abs/2605.07260) | 在相同计算量下试用其他专家，再用任务误差更新分配员 | 不能说首次做等计算量的专家反事实比较 |
| [Exploration-Driven RL for Expert Routing](https://aclanthology.org/2025.findings-emnlp.1282/) | 随机改变部分路由，用答案概率变化训练分配员 | 不能说首次通过扰动路由取得学习信号 |
| [TreeGRPO](https://arxiv.org/abs/2512.08153) | 从扩散过程的一个中间状态分叉，向后 rollout，再把叶子奖励分给前面的动作 | 不能说首次在扩散中用“中间分叉加未来结果”记信用 |
| [BASE Layers](https://arxiv.org/abs/2103.16716) | 让每位专家接收完全相同数量的 token，再做整体分配 | 不能说首次严格控制专家负载 |
| [LOLS](https://arxiv.org/abs/1502.02206) 和 [SEARNN](https://arxiv.org/abs/1706.04499) | 在一个决策点试不同动作，再看未来代价 | 不能把“单次干预后看未来”当成新的通用学习框架 |
| [Routing Divergence Is Not Evidence of Behavioral Influence](https://arxiv.org/abs/2608.15787) | 把路由变化和真正传到最终输出的变化分开，并用行为干预检查影响大小 | 不能用路由翻转率、专家编号变化或路由分数变化代替真实效果 |
| [Geometric and Stochastic Analysis of Discontinuities in Sparse MoE](https://arxiv.org/abs/2606.19036) | 已经分析 top-k 切换边界的不连续，并在边界附近混合额外专家来平滑输出 | 不能把“扩散轨迹会穿过路由边界”或简单边界平滑当作新贡献 |
| [MoECa](https://arxiv.org/abs/2606.15615) | 已经发现扩散 MoE 的专家分支在相邻时间步可重复利用，并按专家分支做缓存 | 不能说首次发现专家功能在扩散轨迹上有跨步冗余 |
| [Nucleus-Image](https://arxiv.org/abs/2604.12163) | 已经把随时间变化的专家分配和专家内部的时间条件计算拆开 | 不能只靠“把选谁和怎样算分开”主张创新 |
| [REFLEX](https://arxiv.org/abs/2608.01784) 和 [TEAM](https://arxiv.org/abs/2602.08404) | 已在扩散语言模型中按去噪进展分配专家计算，并利用相邻去噪步的路由一致性 | 即使对象不是图像，也不能把时间一致性或按去噪进展分配计算本身说成新想法 |
| [ERMoE](https://arxiv.org/abs/2511.10971) | 把路由分数直接绑定到专家学到的子空间 | 不能只把 prototype 换成专家权重或专家子空间的相似度 |
| [FreqOrtho-SR](https://arxiv.org/abs/2606.28745) | 在扩散超分中让多位专家学习互补的正交方向 | 不能只加普通正交约束，就声称解决了专家解耦 |
| [Routers Learn the Geometry of Their Experts](https://arxiv.org/abs/2605.12476) | 证明普通稀疏 MoE 中，router 和被选专家会沿同一个 token 方向收到梯度；还比较了在线 K-Means router | 不能把“prototype 跟着已分配 token 的均值移动”或“router 应贴近 expert 几何”当作新贡献 |
| [Beyond Routing](https://arxiv.org/abs/2608.08853) | 在 Top-8 和 Top-6 语言 MoE 中把“选谁”和“选中后给多大权重”分开，并训练额外聚合头 | 不能把 dispatch/aggregation 解耦、固定专家后的权重 oracle，或额外 aggregation head 当作新贡献 |

DDPO、DPOK 和 DrAFT-K 等扩散强化学习工作也已经研究最终奖励、截断反传和多步信用。仅仅把它们的动作换成专家编号，不够支撑 TPAMI 扩展。

## 目前没有找到的直接组合

截至 2026-08-29，没有找到一篇工作同时做到下面四点：

1. 对象是视觉扩散 MoE。
2. 每个 token 仍只调用一位专家，激活计算量不变。
3. 干预时每位专家收到的 token 数也完全不变。
4. 只交换一次专家身份，然后比较即时效果和未来 2、4、8 步效果。

这只能说明诊断问题可能有空白，不能直接说明训练方法足够新。严格审稿人仍可能把它看成 `TreeGRPO + MoE-GRPO + BASE` 的组合。

## 本检查怎样避免夸大

单独改一个 token 会改变两位专家的负载，因此这里不把结果叫作“单 token 专家因果效应”。每个合法动作都是两个 token 交换专家，完整专家计数向量保持不变。测量对象明确叫“保持负载的分配交换效果”。

候选在看到结果前按固定种子选择。当前步只强制一次；后续全部恢复模型自己的路由。程序同时放入原生副本、强制原生副本和同批次配对副本，测量浮点计算造成的假差异。

## 什么时候立即停止

确认集出现任一情况，就停止“长程专家信用”方向：

1. 即时与 8 步排序仍高度一致。
2. 排名变化没有超过原生副本的数值误差。
3. 方向翻转只来自极少数有效候选。
4. 现象只出现在少数一两层或一个噪声位置。
5. 新检索发现已有视觉扩散 MoE 在严格负载不变时做了同状态专家交换、未来 rollout，并用这个信用训练稀疏路由。

即使确认集通过，也只证明问题存在。下一种训练方法必须另做创新性检查，并包含“使用正确长程依据”和“把同样依据故意打乱”的从头训练对照。没有这两条 500K 结果，不能把性能变化归因于更准确的长程分配。

## 300K 结果出来后怎样解释

这次检查不能只看“即时排序和八步排序是否不同”。还要同时回答三个更严格的问题：

1. 强制交换带来的真实去噪变化，是否明显大于原生副本之间的浮点误差。
2. 变化是否大到值得训练，而不是统计上能检出、实际却几乎不影响模型。
3. 现象是否分布在多层、多种噪声位置和多张图片上，而不是少数异常例子。

如果只是路由编号经常变化，但真实去噪结果几乎不动，就按失败处理。这一点直接回应了 2026 年 8 月的最新证据：路由变化本身不是行为影响。

若确认集通过，下面这些最直接的方案仍然不批准进入 500K 训练：

- 给相邻时间步的路由加普通一致性损失。
- 在路由边界附近改成 top-2 或软混合专家。
- 用前一步较干净的状态直接教当前路由。
- 把 router 变成扩散过程上的普通强化学习策略。
- 给专家输出或权重加一个通用正交损失。

这些做法分别与 SharpMoE、边界平滑、MoE-GRPO、TreeGRPO、ERMoE 或 FreqOrtho-SR 太接近。下一步只有在解释出 ProMoE 自身特有的机制，并能设计“正确依据”和“打乱依据”两条等成本对照后，才值得实现。

## 文献更新后的判断

`Beyond Routing` 让“同一个 router 分数不该同时负责选专家和加权专家”这句话本身不再新。它没有实验 Top-1，也没有研究图像扩散，但只把它搬到 ProMoE 上仍然是换模型复现，不足以成为 TPAMI 方法。

ProMoE 还剩一个更具体、可以被否证的问题：RCL 会根据 router 自己当前的分组，把 prototype 拉向这一组 token 的均值；同一个 prototype cosine 又直接乘在 routed expert 输出上。于是，一个本来只想整理分组的辅助损失，可能顺手改变 shared expert 和 routed expert 的责任比例，而且这个改变未必降低去噪损失。

这个问题与两篇近邻的差别是：

1. `Routers Learn the Geometry of Their Experts` 研究任务损失怎样让普通 router 和 expert 形成共同几何；这里检查的是 ProMoE 额外 RCL 梯度是否与去噪责任方向冲突。
2. `Beyond Routing` 证明预训练语言 MoE 的多专家聚合权重可以改进；这里不先添加聚合头，而是检查 Top-1、shared+routed ProMoE 中，现有 RCL 是否正通过同一个 cosine 造成副作用。
3. 即便这个检查通过，也不能直接声称方法创新。最直接的独立 aggregation head 已被近邻覆盖。后续方法必须利用 ProMoE 的自分组 prototype、去噪责任和专家学习之间的特有关系，并做正确分组与打乱分组的从头训练对照。
